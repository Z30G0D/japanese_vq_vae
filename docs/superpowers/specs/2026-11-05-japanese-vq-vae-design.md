# Japanese Handwritten Character Generation with VQ-VAE — Design

Date: 2026-11-05
Status: Approved, pending implementation plan

## 1. Purpose

Rebuild a 2018 personal project — a convolutional VAE trained on ETL4 handwritten
hiragana — as a VQ-VAE with a class-conditional autoregressive prior. The output is a
clean repository plus a sequel blog post to
["Computer made Japanese letters through Variational Autoencoder"](https://medium.com/@tomernahshon/computer-made-japanese-letters-through-variational-autoencoder-2fdb5b6a0990).

The project's value is the contrast between the original and the rebuild, so the code
must be readable and the results must be presentable as figures.

### What the original did

Two Jupyter notebooks, which could not run in the same environment because `bitstring`
and TensorFlow conflicted on the author's machine.

- Parsed 6,113 ETL4 records with a hand-written `bitstring` unpack, discarding the
  character-code field entirely.
- Preprocessed with Gaussian blur, Otsu `THRESH_TOZERO` thresholding, and a crop of the
  top 72 of 76 rows. Normalized by dividing by 160.
- Trained a TensorFlow 1 graph-mode convolutional VAE: three 64-filter convolutions with
  dropout, a 12-dimensional Gaussian latent, a mirrored transposed-convolution decoder,
  summed squared error plus KL divergence, Adam at 5e-4, 30,000 iterations at batch 32.
- Generated by drawing z from a standard normal and decoding. Reported one plausible さ.

### Weaknesses this project addresses

1. **Labels discarded.** The character code was in every record and was never read, so
   there was no control over which letter was generated and no way to check whether a
   sample was a valid character at all.
2. **No data split.** Training used all 6,113 images with nothing held out, so no
   generalization claim was possible.
3. **Lossy preprocessing.** Otsu thresholding destroys stroke-pressure gradients that
   are precisely what makes handwriting look handwritten.
4. **Prior/posterior mismatch.** The reconstruction term is summed over 5,184 pixels
   while the KL is summed over 12 dimensions, so the KL is effectively negligible. The
   aggregate posterior never matches N(0, I), which means sampling z from a standard
   normal lands off-manifold. This, more than "VAEs are blurry," explains the smudged
   samples.
5. **Notebooks as source.** No tests, no configs, no reproducibility.

Note: the KL expression itself is correct. With `sd = 0.5 * dense(...)`, the term
`-0.5 * sum(1 + 2*sd - mn^2 - exp(2*sd))` is the standard closed form with `2*sd` as log
variance. The problem is term weighting, not the derivation.

## 2. Scope

### Phase 1 (this spec, to be implemented)

Data pipeline, VQ-VAE, and class-conditional transformer prior, producing conditional
samples judged qualitatively from sample grids.

### Phase 2 (documented, deliberately deferred)

Quantitative evaluation and the ported 2018 VAE baseline. Phase 1 must not foreclose
this: the writer-held-out split, config-driven runs, and JSON metric output all exist in
phase 1 even though no metrics are computed yet.

Phase 2 is expected to include reconstruction error on held-out writers, codebook
utilization and perplexity, a CNN classifier scoring whether conditional samples are
recognizable as the requested character, class coverage for the unconditional baseline,
a Fréchet distance in classifier-feature space, and a nearest-neighbor memorization
check.

### Explicitly out of scope

Hierarchical VQ-VAE-2, FSQ or other quantizer variants, writer-style conditioning, a
PixelCNN prior, latent interpolation figures, and any web demo. Writer IDs are carried
through the data pipeline so writer-style conditioning remains possible later, but
nothing in phase 1 consumes them.

## 3. Datasets

### ETL4 — the real dataset

51 hiragana classes, 120 writers, 6,120 samples, 72x76 at 4 bits per pixel, C-type
binary format. Distributed by AIST at `etlcdb.db.aist.go.jp`.

**Access constraints, which shape the design:**

- Download requires accepting the Terms of Use and registering to receive a password.
  There is no anonymous URL.
- Terms of Use clause 5 prohibits redistribution and direct URL links to data files.
  Therefore the repository must never contain the data, must never download it, and the
  blog post must not link to it. Readers register themselves.
- Clause 4 requires the citation: Electrotechnical Laboratory, Japanese Technical
  Committee for Optical Character Recognition, ETL Character Database, 1973-1984.
- As of 2026-11-04 the site returns HTTP 503 from multiple clients and networks. This
  appears to be temporary maintenance rather than a takedown: search indexes carry
  current content, including a Terms of Use revision dated 2025-03-28.

**Verified ingestion instead of download.** The user supplies the zip. Ingestion asserts
size 4,949,352 bytes and MD5 `cede897313b3617e364ddb17b8fad499`, then parses records
directly and writes a cached `.npz`. A mismatch is a hard failure with a message
pointing at the acquisition instructions. The expected size and checksum are taken from
AIST's download listing and are re-confirmed against the real file the first time
ingestion runs.

### Kuzushiji-49 — the development dataset

270,912 images, 49 classes, 28x28, CC BY-SA 4.0, downloadable now from ROIS-CODH. Used
to build and exercise the pipeline while ETL4 access is pending. It is cursive
historical script and not visually equivalent to ETL4, so it is a development
convenience only and no result in the blog post rests on it. It has no writer IDs.

Attribution: "KMNIST Dataset" (created by CODH), adapted from "Kuzushiji Dataset"
(created by NIJL and others), doi:10.20676/00000341.

## 4. Data pipeline

### Interface

A `CharacterDataset` yields `(image, class_id, writer_id, unicode_char)` where
`writer_id` is `None` when the source does not provide it. Two backends implement it,
`Etl4Source` and `K49Source`, selected by a config field. Everything downstream is
written against the interface.

### ETL4 parsing

Records are 2,952 bytes, 6,120 of them, with 4-bit pixels at 72x76. The record layout
and the JIS X 0201 to Unicode mapping tables are vendored from the MIT-licensed
[`choo/etlcdb-image-extractor`](https://github.com/choo/etlcdb-image-extractor) with
attribution, rather than depending on it. That repository pins `Pillow==9.2.0` and
depends on `fsutils`, a personal package installed from GitHub, and was tested only on
Python 3.6.

Two assertions run at ingestion, both targeting suspected defects in the original:

1. **Record count is 6,120.** The 2018 notebook read 6,113, so seven records were
   silently dropped. Ingestion fails loudly on any other count.
2. **Each decoded class appears exactly 120 times.** Records are in a fixed
   writer-major order, so writer identity is recoverable from the record index. This
   check confirms both the class decoding and the writer-order assumption. The exact
   index-to-writer formula is derived empirically from the file during implementation;
   the assertion is what validates it.

### Preprocessing

Decode the 4-bit values, apply the per-record gain field, normalize to [0, 1]. No
Gaussian blur, no Otsu thresholding, no magic constant. Pad 72x76 to square rather than
cropping to 72x72, which in the original could clip strokes. Resize to **64x64** for
clean power-of-two downsampling.

K49 images are padded from 28x28 to 32x32 and used at that size with two downsampling
stages instead of three, which yields the same 8x8 code grid as ETL4 so the prior is
unchanged between the two sources.

No augmentation in phase 1. If the prior overfits, augmentation is the first thing to
revisit, with the caveat that augmenting VQ-VAE training changes the code distribution
the prior is fit to.

### Splits

ETL4 splits **by writer**, 96/12/12 train/val/test, seeded and deterministic, asserted
disjoint with all 51 classes present in each split. Training therefore sees 4,896
images. A random image split would leak the same person's handwriting across train and
test; the original had no split at all.

K49 uses the official train/test split with a validation slice carved out of train, and
supports subsampling N images per class so development runs stay fast.

## 5. Models

### VQ-VAE

- **Encoder:** 64x64x1 through three stride-2 convolutions to an 8x8 grid, with two
  residual blocks, then a 1x1 projection to the embedding dimension.
- **Decoder:** mirrored, with transposed convolutions back to 64x64x1.
- **Quantizer:** codebook of 512 entries at 64 dimensions, EMA updates with decay 0.99
  rather than a codebook loss, straight-through estimator for gradients, commitment
  weight 0.25.
- **Dead-code restarts:** codes unused for a configurable number of steps are
  reinitialized from recent encoder outputs. Utilization is logged every epoch.
- **Loss:** mean squared error on [0, 1] plus the commitment term.

Codebook collapse is the expected failure mode at this data scale — 4,896 images against
512 codes. Restarts plus utilization logging turn a silent failure into a visible one.

**On the 8x8 grid:** 64 tokens per image. A 16x16 grid reconstructs more sharply but
forces the prior to model 256-token sequences from under 5,000 examples, inviting
memorization. The tighter bottleneck pushes codes toward stroke-level structure and
makes generation easier, which is the half that matters. The number of downsampling
stages is a config field so 16x16 is available as an ablation.

### Conditional transformer prior

- Decoder-only causal transformer over the 64 tokens in raster order: 4 layers, 4 heads,
  width 256, a few million parameters.
- Vocabulary is the 512 codes plus a start token.
- Positions use factorized row and column embeddings rather than a flat index, since the
  sequence is a grid.
- Class conditioning is an embedding sized to the dataset's class count (51 for ETL4,
  49 for K49), prepended as the first token.
- Trained with teacher-forced cross-entropy on codes extracted from the frozen,
  fully-trained VQ-VAE.
- **Label dropout of 10%** during training, enabling classifier-free guidance at
  sampling time. Cheap to train and it gives the blog post a guidance-strength sweep
  figure.
- Sampling uses temperature and nucleus filtering, then decodes the completed grid.

The prior is what makes the VQ-VAE generative at all. The VQ-VAE alone has no
distribution over code grids, and grids sampled uniformly decode to noise because valid
grids are the vanishingly small subset with spatially coherent stroke structure.

## 6. Repository and tooling

```
jvqvae/
  data/      sources/{etl4,k49}.py, dataset.py, splits.py, ingest.py, jis.py, etl_format.yml
  models/    vqvae/{encoder,decoder,quantizer,model}.py, prior.py
  train/     vqvae.py, prior.py
  sample.py  config.py  device.py
configs/     etl4_vqvae.yaml, etl4_prior.yaml, k49_dev.yaml
tests/  notebooks/  results/  data/ (gitignored)
```

A small installable package, with notebooks reserved for blog-post figures rather than
holding the implementation. Managed with `uv` and a `pyproject.toml`, Python 3.11+.
Dependencies limited to torch, numpy, pillow, pyyaml, matplotlib and pytest; no
experiment-tracking service.

Configs are YAML parsed into dataclasses so every run is reproducible from a file.
Metrics and run metadata are written as JSON into `results/` from phase 1 onward, even
though phase 1 computes no evaluation metrics. `device.py` selects MPS, CUDA or CPU
automatically.

A thin CLI exposes `ingest-etl4`, `train vqvae`, `train prior`, and `sample`.

**Target hardware:** an Apple Silicon Mac using the MPS backend. Model sizes above are
chosen to train in minutes to low tens of minutes at this data scale. The device
abstraction keeps a rented GPU available later without code changes.

### Tests

Small suite targeting failure modes that are otherwise invisible:

- **Causal masking.** Perturbing token *i* must leave logits for tokens before *i*
  unchanged. A broken mask yields an excellent training loss and garbage samples, and is
  the most common silent failure in autoregressive models.
- Straight-through gradients reach the encoder.
- EMA codebook updates move cluster centers toward the batch mean.
- Train/val/test writer sets are disjoint and every split contains all 51 classes.
- End-to-end shape round-trip on a tiny synthetic fixture, so the suite runs without
  ETL4 present.

### README

Carries ETL4 acquisition instructions (register with AIST directly; the repository
cannot ship or link the file), the AIST citation required by clause 4, and attribution
for the vendored format tables and for K49.

## 7. Phase 1 definition of done

- `ingest-etl4` verifies the supplied zip, parses 6,120 records, passes both assertions,
  and writes the cache.
- The K49 path runs end to end without ETL4 present.
- The VQ-VAE trains on ETL4 and reconstructs held-out writers recognizably, with
  codebook utilization logged and not collapsed.
- The prior trains on extracted codes and produces a grid of conditional samples
  covering all 51 hiragana.
- A guidance-strength sweep figure for a single character.
- Test suite passes.
